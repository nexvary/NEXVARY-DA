# Stages 351-400 — Usability First

The product criterion for this milestone is not feature count. It is reducing the technical knowledge required to complete common work.

## 351-365 — GUI-ready settings

- Persistent non-secret integration settings under `.nexvary-da/integrations.json`.
- Environment variables still override saved values for managed deployments.
- API keys, passwords, tokens, and credentials are deliberately rejected from persistent integration settings.
- FastMCP, Cua, Oya, VoiceStudio, and MoneyPrinter adapters read the same graphical settings.

## 366-380 — Easy Mode

- Easy Mode is now the default desktop experience.
- Terminal, agent pool, raw engine controls, and engineering telemetry move behind Advanced Mode.
- The home screen begins with user intentions: Start a task, Build & Test, Automation & Media, Tools & Integrations, Release Check, Add Project.
- Engine selection is automatic for Easy Mode tasks: Hybrid when ZCode is available, otherwise Native.
- Advanced Mode remains one click away and no capability was removed.

## 381-390 — Setup Center

- Graphical setup center for the six Stage 350 integration families.
- File/folder pickers replace manual path/environment-variable editing.
- Oya API key can be entered for the current session but is never written to `integrations.json`.
- Readiness explains missing permissions, missing files/packages, and session credentials in visible status text.
- Qwen commercial-license boundary remains visible in the GUI.

## 391-395 — Graphical Tool Box

- Desktop inspection: list apps and inspect desktop using safe Cua calls.
- Browser form: website + plain-language task + optional reusable playbook.
- Image form: prompt + output path + configured model/device.
- Video form: plain-language subject.
- Voice form: visible service status and connection check.
- MCP form: server file/endpoint + transport + Start button.
- Long-running calls run in worker threads so the desktop window remains responsive.

## 396-400 — Verification and UX gate

- Runtime UI probe remains the acceptance mechanism for clipping, overlap, dead callbacks, screenshot evidence, and current-source fingerprinting.
- Windows and Ubuntu CI, native executable packaging, Windows installer smoke test, and Debian package smoke test remain mandatory.
- Stage 400 is accepted only when the exact branch head passes those checks.

## Design rule

When a workflow can be represented safely as a choice, form, picker, wizard, status card, or one-click action, the GUI should be the primary path. CLI remains an expert/automation surface, not the normal-user requirement.
