# NEXVARY-DA Engineering Stages 251–300

These are implementation and verification checkpoints, not cosmetic counters.

## 251–260 — Runtime desktop UI inspection

- Real Tk runtime window construction.
- Widget-tree inventory after geometry resolution.
- Window-relative geometry collection.
- Clipping / off-window detection.
- Zero-size widget detection.
- Minimum interactive-target warnings.
- Missing Button callback detection.
- Sibling interactive-overlap detection.
- Probe-safe control invocation.
- Runtime UI evidence persisted into project state.

## 261–275 — Visual evidence gate

- Optional PNG capture through Pillow ImageGrab.
- Screenshot SHA-256 evidence.
- Render-variation sanity check to reject blank/uniform captures.
- Source-root SHA-256 bound to UI evidence.
- Strict Release Gate accepts UI evidence only when it matches the current source fingerprint.
- Stale UI evidence cannot satisfy Release READY.
- Linux CI runs the actual UI under Xvfb at 1920x1080.
- Linux CI requires a real screenshot.
- Windows CI runs runtime geometry/interaction probing.
- UI probe screenshot is uploaded as a CI artifact.

## 276–286 — Android runtime UI harness

- ADB device inventory parsing.
- UIAutomator XML hierarchy capture.
- Typed node model: text, content-description, resource id, class, enabled/clickable state and bounds.
- Label/resource-id search.
- Center-point calculation.
- Tap by coordinates.
- Tap by matched label.
- Android Back key action.
- Explicit component launch.
- Binary ADB screenshot capture.
- PNG validation and workspace-bound atomic screenshot storage.
- Android UI actions require the independent ADB permission.
- Android screenshots additionally require workspace Write permission.

## 287–295 — Native application packaging

- PyInstaller one-file native executable on Windows and Linux.
- Native executable smoke test via `--help`.
- Portable Windows ZIP and Linux tar.gz bundles.
- SHA-256 bundle sidecar.
- NSIS Windows Setup package.
- CI silent install / executable smoke / uninstall of the Windows Setup.
- Debian `.deb` package.
- CI dpkg install / executable smoke / package removal.
- License, security and third-party notices included with portable packages.

## 296–300 — Signing readiness and release boundary

- Production signing readiness inspection without exposing secret values.
- Windows readiness checks for SignTool plus certificate/password references.
- Linux readiness checks for GPG plus configured signing key id.
- Project Doctor reports signing readiness.
- CLI exposes `signing-status`.
- MCP exposes signing-readiness evidence.
- CI packages are deliberately marked unsigned unless real external signing credentials are supplied.
- No self-signed certificate is substituted for production code signing.

## Stage 300 completion rule

Stage 300 means the desktop runtime UI probe, Android UI automation layer, native executable pipeline and installable package pipeline are implemented and cross-platform CI-verified.

It does **not** mean production code signing is complete. A production certificate/private key must be supplied through an external secret/credential channel. Live Android-device interaction is also target-dependent; the ADB harness is regression-tested in CI, while a real device/emulator run requires an attached authorized target.
