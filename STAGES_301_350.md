# Stages 301-350 — Automation and Media Fabric

These stages extend the verified Stage 300 baseline. They are engineering checkpoints, not cosmetic numbering.

## 301-310 — Plugin Hub

- Built-in inventory for FastMCP, Cua Driver, Oya Browser, VoiceStudio, Qwen-Image 2.1, and MoneyPrinterTurbo.
- Capability, upstream, license, environment, executable, and permission metadata.
- Status-only custom manifests under .nexvary-da/plugins.
- No automatic downloads, package installation, model download, or network probing.
- Plugin status never exposes API-key values.

## 311-320 — FastMCP Gateway

- Workspace-bound FastMCP server target validation.
- STDIO and HTTP launch through the existing managed-process registry.
- HTTPS required for non-loopback remote targets.
- Non-loopback HTTP server bind is fail-closed without explicit approval and network permission.
- External FastMCP remains optional and is not a hard dependency.

## 321-330 — Cua Computer Use

- Dedicated Cua Driver adapter behind shell and desktop_automation permissions.
- Explicit read-only and mutating tool allowlists.
- Mutating mouse/keyboard/window actions require a second allow_mutation opt-in.
- Screenshot output is constrained to the approved workspace and requires write permission.
- No fallback to unguarded OS automation.

## 331-338 — Oya Browser

- Local @oya-ai/browser SDK bridge using an already-installed Node package.
- HTTPS required for non-loopback browser tasks.
- Prompt/task payload is written only to a short-lived .nexvary-da file and removed after execution.
- Optional toPlaybook recording path.
- NEXVARY does not copy browser credentials, cookies, MFA secrets, or persona storage.

## 339-346 — Media adapters

- VoiceStudio loopback/HTTPS API bridge without vendoring AGPL source.
- Qwen-Image 2.1 optional Diffusers launcher with explicit research/non-commercial license warning.
- Qwen weights are never bundled by NEXVARY.
- MoneyPrinterTurbo CLI adapter requires its checkout to live inside the approved workspace.
- Media actions preserve the same Shell, Write, and Network permission boundaries.

## 347-350 — Unified status, audit, and delivery

- Integration inventory is exposed to CLI/MCP/UI.
- Runtime event logging records tool names, result codes, and metadata but not secrets or full prompts.
- Third-party license boundaries are documented.
- Windows and Ubuntu CI remain the acceptance gate.

## Completion rule

Stage 350 is accepted only when the exact branch head compiles, passes unit/integration tests on Windows and Ubuntu, passes native packaging checks, and does not weaken Stage 300 release/security boundaries. Presence of external tools is not required for CI; their adapters are verified with mocks and fail closed when dependencies or permissions are absent.
